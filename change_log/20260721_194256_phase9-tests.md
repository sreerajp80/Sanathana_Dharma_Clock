# Change log — Phase 9: Tests

**Date:** 2026-07-21
**Plan:** [../plans/20260721_194256_phase9-tests.md](../plans/20260721_194256_phase9-tests.md)
**Phase:** 9 of the [implementation plan](../docs/implementation_plan.md)

## What changed

This is a test-only phase. No `lib/` source was changed. It fills the two
remaining Phase 9 gaps and makes the `test/` tree mirror `lib/`.

### New files

- `test/models/saved_location_test.dart` — `SavedLocation` JSON round-trip
  (with and without a label), defensive `fromJson` (missing fields → `0.0` /
  empty label, wrong-typed fields fall back, integer coordinates become
  double), value equality / `hashCode`, and that `toString()` omits the
  coordinates (security rule).
- `test/models/display_settings_test.dart` — `DisplayMode` `storageValue` →
  `fromStorage` round-trip for every value, and the corrupt-pref fallback to
  `DisplayMode.both` for `null`, empty, and unknown strings.
- `test/screens/clock_screen_test.dart` — widget tests for `ClockScreen`,
  driving the real `clockProvider` through the existing fake-clock seam
  (`nowProvider` + `effectiveLocationProvider`) and seeding the display mode
  into a mock `SharedPreferences`. Covers: both mode renders the readout and
  the dial; the saved-location and the "no location — midnight-anchored day"
  footers; and that analog / digital modes hide the readout / dial.
- `test/screens/settings_screen_test.dart` — widget tests for `SettingsScreen`
  over an empty mock `SharedPreferences`. Covers: the three section cards
  render, the Location card shows the live toggle and empty saved state, the
  Display card shows the three options, the About tile renders, and tapping a
  display option updates `displayModeProvider`.

### Notes / decisions

- The `test/helpers/` folder from the plan was not needed — the date/UTC helper
  tests already live under `test/core/utils/`, mirroring where the helpers sit
  in `lib/`.
- Screen widget tests were placed under `test/screens/` (mirroring
  `lib/screens/`) rather than `test/widgets/`; the plan's "widgets" label was
  about widget-level tests, and mirroring `lib/` was the stated priority.
- The settings test uses a tall test surface (`tester.view.physicalSize`) so the
  lazy `ListView` builds and lays out the off-screen About card; the size is
  reset on teardown.
