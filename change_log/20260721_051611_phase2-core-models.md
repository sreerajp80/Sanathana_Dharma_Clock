# Change log — Phase 2: Core models

**Date:** 2026-07-21
**Plan:** [../plans/20260721_051225_phase2-core-models.md](../plans/20260721_051225_phase2-core-models.md)
**Phase:** 2 of the [implementation plan](../docs/implementation_plan.md).

## What changed

Created the three immutable data types Phase 2 calls for. No math, no services, no
UI — those come in later phases.

### Files created

- `lib/models/dharma_time.dart` — `DharmaTime`, one immutable clock reading. Holds
  `ghatika`, `vinadi`, `prana`, `muhurta`, `fraction` (0–1 through the day), `span`,
  `ghatikaLen`, and `sunrise`. `const` constructor, value `==` / `hashCode` (via
  `Object.hash`), and a plain-ASCII `toString()`. No JSON — it is always computed, never
  saved.
- `lib/models/saved_location.dart` — `SavedLocation` (latitude, longitude, label) with
  `toJson` and a defensive `fromJson` that falls back per field (coordinates accept
  `int` or `double`), mirroring `AppConfig.fromJson`. Value `==` / `hashCode`. Its
  `toString()` deliberately omits the coordinates so a stray log cannot leak the position.
- `lib/core/constants/app_constants.dart` — `AppConstants` (a non-instantiable
  `abstract final class`) with the pref keys (`saved_location`, `use_live_location`,
  `display_mode`) and the dharma-time nesting numbers plus `secondsPerDay = 86400` for
  the polar-day fallback.

### Files edited

- None. `docs/implementation_progress.md` was updated to tick the Phase 2 boxes.

## Verification

- `flutter analyze` — clean, no issues found.
- No tests added; the `SavedLocation` round-trip test is scheduled for Phase 9, and the
  math tests for Phase 3, per the implementation plan.

## Hard rules honoured

- Offline / open source — no packages added; pure Dart types.
- Location on device — `SavedLocation.toString()` omits coordinates.
- Never crash on bad data — `SavedLocation.fromJson` falls back per field.
- Immutable models — all fields `final`, `const` constructors.
