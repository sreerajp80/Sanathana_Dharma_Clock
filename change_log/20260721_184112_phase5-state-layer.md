# Change log — Phase 5: State layer (Riverpod)

**Date:** 2026-07-21
**Implements:** [../plans/20260721_184112_phase5-state-layer.md](../plans/20260721_184112_phase5-state-layer.md)
**Phase:** 5 of [../docs/implementation_plan.md](../docs/implementation_plan.md)

## What changed

Wired the Phase 3 math and the Phase 4 location layer to the (future) UI through
Riverpod, with a correct ticking clock, a once-per-day sunrise recompute, lifecycle
handling, and global error handlers.

### New files

- `lib/providers/service_providers.dart` — plain providers for the stateless services:
  `solarCalculatorProvider`, `timeCalculatorProvider`, `locationServiceProvider`, and
  `locationRepositoryProvider` (the last reads the root `sharedPreferencesProvider`).
- `lib/models/display_settings.dart` — `DisplayMode { analog, digital, both }` with
  string parse/serialize; unknown/missing → `both`.
- `lib/providers/settings_providers.dart` — `SettingsNotifier` / `displayModeProvider`:
  reads the display mode from prefs on build and persists changes.
- `lib/providers/location_providers.dart` — `LocationState`, `LocationNotifier`
  (`refreshLive`, `setUseLive`, `saveLocation`, `clear`), and `effectiveLocationProvider`
  running `LocationResolver.resolve` (live → saved → none).
- `lib/models/clock_snapshot.dart` — immutable `ClockSnapshot` (civil time, `DharmaTime`,
  `isPolar`, location `source`) with value equality.
- `lib/providers/clock_providers.dart` — `nowProvider` (injectable clock) and
  `clockProvider`: the once-per-second tick, the cached `SolarDay` re-resolved only on the
  day-boundary roll, the no-location midnight fallback, and `AppLifecycleListener`
  pause/resume handling.

### Modified files

- `lib/main.dart` — added the global error handlers `FlutterError.onError` and
  `WidgetsBinding.instance.platformDispatcher.onError` (architecture §10). Verbose detail
  is gated behind `AppFlavorConfig.enableVerboseLogging`; no coordinates are logged. The
  placeholder home screen is unchanged (the real clock screen is Phase 6).
- `docs/implementation_progress.md` — Phase 5 ticked and set to Done; status overview,
  overall-status line, and a dated note updated.

### New tests (15 added; 33 → 48 total, all green)

- `test/providers/settings_providers_test.dart` — default `both`, reads stored mode,
  unknown → `both`, `setMode` persists.
- `test/providers/location_providers_test.dart` — resolve chain (none → null, saved,
  live-preferred, live-fails → saved), `setUseLive` persistence, `saveLocation`, `clear`
  (uses an injected fake `LocationService` and mock prefs).
- `test/providers/clock_providers_test.dart` — snapshot `dharma` equals `TimeCalculator`
  output for the resolved day, no-location gives a midnight/polar snapshot, the anchor is
  cached within a day, and it rolls when `now` crosses into the next day.

## Decisions and deviations

- **`ClockSnapshot` instead of a bare `DharmaTime`.** The plan text said the tick produces
  `DharmaTime`; the tick emits a `ClockSnapshot` superset so the readout also has the
  ticking civil time, the polar flag, and the location source. Documented in the plan.
- **No logging package.** Global error handlers use `debugPrint` gated by the flavor, to
  avoid adding a dependency in this phase.
- **`PlatformDispatcher` access.** Used `WidgetsBinding.instance.platformDispatcher.onError`
  rather than `import 'dart:ui'`, to avoid name clashes with `package:flutter/material.dart`.
- **No-location fallback** builds a midnight-anchored `SolarDay` inline (fixed 86,400 s),
  mirroring `SolarCalculator`'s polar fallback shape, rather than adding a public method to
  the Phase 3 service.
