## What is the issue

Phase 1 left an empty `lib/models/` folder and no `lib/core/constants/` file. The rest
of the app (services, providers, screens) needs three data types before it can be built:

- a reading of dharma time (Ghaṭikā : Vināḍī : Prāṇa : Muhūrta),
- the saved location record, and
- the shared constants (preference keys and thresholds).

Phase 2 only creates these plain data types. It writes **no** math, no services, no UI.
The solar and mapping math is Phase 3.

## The plan for each file

### 1. `lib/models/dharma_time.dart`

An immutable value type holding one reading, recomputed each tick by the Phase 3
`TimeCalculator`. It carries both the four dharma units and the context needed to draw
the dial (span, Ghaṭikā length, sunrise). It holds data only — no solar or mapping math.

Fields (all `final`):

- `int ghatika` — 0–59, the Ghaṭikā.
- `int vinadi` — 0–59, the Vināḍī.
- `int prana` — 0–5, the Prāṇa.
- `int muhurta` — 0–29, the Muhūrta (= `ghatika ~/ 2`).
- `double fraction` — 0.0–1.0, progress through the whole dharma day (for the smooth
  fast hand and the rim "now" marker).
- `Duration span` — the sunrise-to-next-sunrise length of this dharma day
  (≈ 24 h, elastic).
- `Duration ghatikaLen` — one Ghaṭikā = `span / 60` (kept so the dial does not
  recompute it).
- `DateTime sunrise` — today's anchoring sunrise (local time, for the "Sunrise 06:11"
  readout).

Members:

- A `const` constructor with all fields `required`.
- `==` / `hashCode` by value (so Riverpod can skip rebuilds when the reading is
  unchanged). Use `Object.hash` for `hashCode`.
- `toString()` for debugging (e.g. `Gh 24 : Vi 18 : Pr 3 (M12)`), plain ASCII.

No `copyWith`, no JSON — `DharmaTime` is always computed, never persisted, so it needs
neither. Keeping it minimal matches the architecture note "no logic beyond mapping."

### 2. `lib/models/saved_location.dart`

An immutable record of the one saved place, persisted by the Phase 4
`LocationRepository` as a small JSON string in `shared_preferences`.

Fields (all `final`):

- `double latitude`
- `double longitude`
- `String label` — a short human name (e.g. a city or "Saved location"); may be empty.

Members:

- A `const` constructor with `latitude` and `longitude` `required`, `label` defaulting
  to `''`.
- `Map<String, dynamic> toJson()` — `{'latitude': ..., 'longitude': ..., 'label': ...}`.
- `factory SavedLocation.fromJson(Map<String, dynamic> json)` — defensive, mirroring
  `AppConfig.fromJson`: read each field with a type check and fall back
  (`0.0` / `0.0` / `''`) on a missing or wrong-typed value, so a corrupt pref never
  crashes the app. Accept `int` or `double` for the coordinates (`num` → `toDouble()`).
- `==` / `hashCode` by value; `toString()` **without** exact coordinates
  (e.g. `SavedLocation(label: Kochi)`), to honour the "never log exact coordinates"
  rule — a stray `toString()` in a log must not leak the position.
- `copyWith` is **not** added unless a later phase needs it (keep the model lean).

### 3. `lib/core/constants/app_constants.dart`

A single `abstract final class AppConstants` (no instances) holding the technical
constants so keys and magic numbers live in one place:

- Preference keys (used later by the repository / settings):
  - `prefSavedLocation = 'saved_location'`
  - `prefUseLiveLocation = 'use_live_location'`
  - `prefDisplayMode = 'display_mode'`
- Clock / solar thresholds (used later by Phase 3/5):
  - `secondsPerDay = 86400` — the fixed span fallback for a polar no-sunrise day.
  - `ghatikaPerDay = 60`, `vinadiPerGhatika = 60`, `pranaPerVinadi = 6`,
    `muhurtaPerDay = 30` — the nesting from idea doc §1.

These are the values the plan and idea doc already name; no new behaviour is invented.
Grouping them now keeps later phases from hard-coding literals.

## How this respects the hard rules

- **Offline only / open source only** — no packages are added; these are pure Dart
  types.
- **Location stays on the device** — `SavedLocation.toString()` deliberately omits the
  coordinates so logging it cannot leak the position.
- **Never crash on bad data** — `SavedLocation.fromJson` falls back per field like
  `AppConfig.fromJson`, so a corrupt saved record degrades safely.
- **Immutable models** — every field is `final`, constructors are `const`; readings are
  recomputed, never mutated (architecture §11, CLAUDE.md architecture rules).

## Style

- `package:` imports only (none needed here), single quotes, `final` fields, `const`
  constructors — matches `app_config.dart`.
- File names `snake_case`, classes `PascalCase` — already followed.
