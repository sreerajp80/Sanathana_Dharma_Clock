# Phase 9 — Tests

**Status:** completed

## What this phase is

Phase 9 of the implementation plan is "Tests". The goal is to cover the
critical, high-risk areas before release, and to make the `test/` tree mirror
`lib/`. See [../docs/implementation_plan.md](../docs/implementation_plan.md)
Phase 9 and the progress checklist in
[../docs/implementation_progress.md](../docs/implementation_progress.md).

## What already exists (no change needed)

The math and state layers are already well tested (48 tests, all green):

- Sunrise math vs NOAA reference + polar + before-sunrise —
  `test/services/solar_calculator_test.dart`
- Dharma-time mapping + reverse + day boundary —
  `test/services/time_calculator_test.dart`
- Date/UTC helpers — `test/core/utils/date_utils_test.dart`
- Location resolver chain — `test/services/location_resolver_test.dart`
- `LocationRepository` round-trip / corruption / clear —
  `test/repositories/location_repository_test.dart`
- Providers (clock mapping, no-location fallback, day roll, settings
  persistence, location resolve) — `test/providers/*_test.dart`

So the required "sunrise math", "dharma mapping + reverse", and "edge cases"
checklist items are already met. This phase fills the two real gaps.

## The gaps (the issue)

Two Phase 9 checklist items are not yet covered, and `test/` does not yet
mirror `lib/models`, `lib/screens`, or `lib/widgets`:

1. **No model tests.** There is no `test/models/` folder. The
   `SavedLocation` JSON round-trip test is explicitly required by the plan and
   is missing. `DisplayMode` storage round-trip is also untested at the model
   level.
2. **No widget tests.** There is no `test/screens/` (or `test/widgets/`)
   folder. The clock readout and the Settings cards are untested in the UI.

## The plan (files to add)

All new files. No `lib/` source changes — this is a test-only phase. New tests
mirror `lib/` structure.

### 1. `test/models/saved_location_test.dart` (new)

- `toJson` → `fromJson` round-trip returns an equal `SavedLocation` (with and
  without a label).
- Defensive `fromJson`: missing fields fall back to `0.0` / empty label;
  wrong-typed fields (e.g. a string latitude) fall back safely; `int`
  coordinates are accepted and become `double`.
- Value equality and `hashCode` (equal values are equal; a differing field is
  not).
- `toString()` does **not** contain the coordinates (security rule) — assert it
  omits the latitude/longitude numbers.

### 2. `test/models/display_settings_test.dart` (new)

- `storageValue` → `fromStorage` round-trip for every `DisplayMode` value.
- `fromStorage(null)` and `fromStorage('garbage')` both fall back to
  `DisplayMode.both` (corrupt-pref safety).

### 3. `test/screens/clock_screen_test.dart` (new)

- Pump `ClockScreen` inside a `ProviderScope` + `MaterialApp`, driving the real
  `clockProvider` through the same seam the provider tests use:
  `nowProvider.overrideWithValue(() => fixedInstant)` and
  `effectiveLocationProvider.overrideWithValue(<saved Kochi location>)`. This
  reuses the existing, proven fake-clock approach rather than inventing a new
  one.
- With `displayModeProvider` at its default (`both`): the readout text renders
  (find the "Ghaṭikā" / "Muhūrta" labels) and the anchor footer shows
  "Saved location".
- With `effectiveLocationProvider` overridden to `null`: the footer shows the
  "No location — midnight-anchored day" text (hard rule 4 surfaced in the UI).
- Override `displayModeProvider` to `analog` and to `digital` and check the
  readout is hidden / the dial is hidden respectively (assert on the readout
  text being absent / present). `displayModeProvider` will be overridden with a
  small fake `SettingsNotifier`-free approach: override `sharedPreferencesProvider`
  with a mock `SharedPreferences` seeded with the wanted mode string, so the
  real notifier builds that value. (Keeps the override to one line and touches
  no production code.)
- Note: the clock's 1-second `Timer.periodic` is cleaned up when the
  `ProviderScope` disposes at test teardown; the test never advances time, so the
  timer does not fire. If the framework still reports a pending timer, wrap the
  body in `tester.runAsync` or assert after a single `pump()` — chosen during
  implementation to keep the test green.

### 4. `test/screens/settings_screen_test.dart` (new)

- Seed `SharedPreferences.setMockInitialValues({})`, get the instance, and
  override `sharedPreferencesProvider` with it so `LocationNotifier` and
  `SettingsNotifier` build against a real (empty) mock store. No production
  code changes; the location plugin is never called on a plain render.
- Pump `SettingsScreen` in a `ProviderScope` + `MaterialApp`.
- Assert the three card titles render: "Location", "Display", "About".
- Assert the Location card shows "Use live location" and "No saved location";
  the Display card shows the three radio options; the About card shows "About
  this app".
- Tap "Readout only" and verify `displayModeProvider` reads back
  `DisplayMode.digital` (the notifier updated state). This proves the card is
  wired to the provider, not just static text.

## Out of scope

- No dial-painter pixel/golden test — a `CustomPainter` golden is brittle and
  not on the Phase 9 checklist; the dial is already exercised indirectly by the
  clock-screen render.
- Phase 10 (release hardening) is separate.
