## The issue / goal

The repository has docs and the guidelines submodule, but **no Flutter app source**
yet — there is no `lib/`, no `pubspec.yaml`, no `android/` project. Phase 1 must produce a
running Flutter app skeleton with:

- the correct namespace / applicationId,
- `dev` and `prod` flavors,
- the core dependencies,
- the standard `lib/` folder layout,
- the data-driven About config (`AppConfig` + `ConfigService`),
- a clean `flutter analyze`.

No clock math, no UI screens, no location yet — those are later phases. Phase 1 is only
the scaffold and config.

## The plan for the fix

### Step 1 — Generate the Flutter project

Run `flutter create` in the repo root without clobbering the existing docs/plans:

```
flutter create --org in.sreerajp --project-name sanathana_dharma_clock \
  --platforms android --android-language kotlin .
```

- `--org in.sreerajp` + project name `sanathana_dharma_clock` gives applicationId /
  namespace `in.sreerajp.sanathana_dharma_clock`.
- `--platforms android` only (Android-only app; no iOS/web/desktop/linux/windows folders).
- Existing files (`CLAUDE.md`, `docs/`, `plans/`, `change_log/`, `.git`, `.gitmodules`,
  `docs/guidelines/` submodule) are left untouched by `flutter create` — it only adds
  missing scaffold files.

### Step 2 — Flavors in Gradle

Edit `android/app/build.gradle.kts` (per flavors guide "Android Flavor Setup"):

- Add `flavorDimensions += "environment"`.
- `dev` flavor: `applicationIdSuffix = ".dev"`, `versionNameSuffix = "-dev"`,
  `resValue("string", "app_name", "Sanathana Dharma Clock Dev")`.
- `prod` flavor: `resValue("string", "app_name", "Sanathana Dharma Clock")`.
- Add the `signingConfigs { create("release") { ... } }` block that reads
  `android/key.properties` **only if it exists** (Strategy A). No keystore is created in
  Phase 1 (that is Phase 10) — the guard just means release builds fall back to debug
  signing until the keystore exists. Debug builds and both flavors' `flutter run` work with
  no signing setup.
- Point the manifest app label at `@string/app_name` and remove the hard-coded
  `android:label` so the flavor string wins.
- Set `minSdk = 24` and `targetSdk = 35` (per CLAUDE.md identity table).

> Note: I will **not** enable `isMinifyEnabled`/ProGuard or the prod-release signing guard
> in Phase 1 to keep the scaffold building cleanly without a keystore. Those harden in
> Phase 10. I will note this deviation so it is not forgotten.

### Step 3 — Dependencies in `pubspec.yaml`

Add, latest stable compatible with Dart 3.11:

- `flutter_riverpod`
- `go_router`
- `geolocator`
- `shared_preferences`
- `package_info_plus`

Each is open source (BSD/MIT/Apache) and none pulls an HTTP client into the app. I will
confirm with `flutter pub deps` that no networking package (dio, http, etc.) is pulled in
transitively into the app runtime. Register the asset folder:

```yaml
flutter:
  assets:
    - assets/config/
```

### Step 4 — `lib/` skeleton

Create the folder layout from architecture §4 / guideline §3:
`core/config`, `core/constants`, `core/utils`, `models`, `services`, `repositories`,
`providers`, `screens`, `widgets`, `theme`, plus `main.dart`. Empty folders get a
`.gitkeep` so they are tracked; they are replaced by real files in later phases.

### Step 5 — About config (data-driven)

- `assets/config/app_config.json` with `appName`, `description`, `version` (`1.0.0`),
  `build` (`1`), and a `details` map (Author, Email = `sreerajp@zohomail.in`, License,
  AI used, IDE used). Keep `version`/`build` in sync with `pubspec.yaml`.
- `lib/core/config/app_config.dart` — `AppConfig` exactly per guideline §1.4 (immutable,
  `fromJson`, `fallback`).
- `lib/core/config/config_service.dart` — `ConfigService` exactly per guideline §1.5
  (`load()`, `loadAndVerify()`, injectable asset loader).

### Step 6 — Flavor config + thin `main.dart`

- `lib/core/config/app_flavor_config.dart` — `AppFlavorConfig` per engineering standard
  §5.2 (reads `APP_FLAVOR` then `FLUTTER_APP_FLAVOR`, defaults `prod`).
- `lib/main.dart` — the init sequence from architecture §5:
  1. `WidgetsFlutterBinding.ensureInitialized()`
  2. read `AppFlavorConfig.instance`
  3. load `SharedPreferences`
  4. `ConfigService().loadAndVerify()` → `AppConfig`
  5. `runApp(ProviderScope(overrides: [...], child: ...))`
  A minimal placeholder home screen (a `Scaffold` showing the app name + flavor) stands in
  until Phase 6 builds the real clock screen. This keeps `main.dart` thin.

### Step 7 — Lint + verify

- Keep the generated `analysis_options.yaml` (`package:flutter_lints`), adjust only if
  needed for the scaffold.
- Run `flutter pub get`, `dart format .`, `flutter analyze` (must be zero warnings).
- Confirm both flavors build far enough to prove wiring: `flutter analyze` clean, and if a
  device/emulator is available I will attempt `flutter run --flavor dev`. If no device is
  available I will instead run `flutter build apk --flavor dev --debug` to prove the flavor
  compiles, and note that a device run was not possible.

### Step 8 — Update trackers

- Tick the Phase 1 items in [../docs/implementation_progress.md](../docs/implementation_progress.md)
  and set Phase 1 status to Done (or In progress if a device run is pending).
- Write the change log in `change_log/`.
