# Plan — Phase 4: Location

**Status:** completed

Date: 2026-07-21
Phase: 4 of 10 (see [docs/implementation_plan.md](../docs/implementation_plan.md))

## The issue (what is missing)

Phases 1–3 built the app skeleton, the models, and the pure clock math. The math
(`SolarCalculator.resolveDay`) already handles the polar-day and before-sunrise
fallbacks. But the app still has **no way to get a place to run from**:

- No `LocationService` to read the device GPS (with permission asked at point of use).
- No `LocationRepository` to save and read the one saved location in
  `shared_preferences` (widgets must never touch prefs directly).
- The Android manifest has **no location permission** yet.
- Nothing decides the fallback chain **live → saved → none (midnight day)**.
- The saved location is **not excluded from Android cloud backup**.

This phase fills those gaps. It stays offline (GPS is not network) and keeps the
location on the device.

## Files to change / add

**New source files**

1. `lib/services/location_service.dart` — `LocationService`: a thin wrapper over
   `GeolocatorPlatform.instance`. Checks that location service is on, checks/requests
   permission at the point of use, and returns the current fix. Knows nothing about
   `shared_preferences`, `BuildContext`, routes, or UI strings (architecture §7).
   - Add a small result type `LocationResult` + enum `LocationStatus`
     (`success`, `serviceDisabled`, `permissionDenied`, `permissionDeniedForever`,
     `error`) so the caller can react without exceptions. On `success` it carries
     `latitude`/`longitude` only (no label — a live fix has no name).

2. `lib/repositories/location_repository.dart` — `LocationRepository`: the only
   place that reads/writes the saved location and the "use live location" flag in
   `shared_preferences`, using the existing keys in `AppConstants`
   (`prefSavedLocation`, `prefUseLiveLocation`). Methods:
   - `SavedLocation? readSavedLocation()` — defensive JSON decode; returns `null` on
     missing/corrupt data.
   - `Future<bool> writeSavedLocation(SavedLocation)`.
   - `Future<bool> clearSavedLocation()` — for the Settings "clear" action
     (security.md §13).
   - `bool readUseLiveLocation()` (default `false`).
   - `Future<bool> writeUseLiveLocation(bool)`.

3. `lib/services/location_resolver.dart` — a **pure** helper that picks the effective
   coordinates from the fallback chain, fully testable with no plugin/prefs:
   `EffectiveLocation? resolve({required bool useLive, LocationResult? live, SavedLocation? saved})`.
   - If `useLive` and the live fetch succeeded → live coordinates.
   - Else if a saved location exists → saved coordinates.
   - Else → `null` (no anchor). The caller then uses a midnight-anchored day, which
     `SolarCalculator` already produces via its fixed-span fallback. This keeps hard
     rule 4 ("never crash on a missing anchor") satisfied end to end.

**Android config**

4. `android/app/src/main/AndroidManifest.xml`
   - Add `ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION` uses-permission entries.
   - Add `android:allowBackup="false"` to the `<application>` tag to keep the saved
     location off Android cloud backup (security.md §10 — "prefer false"). This is the
     simplest strong guarantee for an offline clock with nothing worth restoring.
     (No `xmlns:tools` / `tools:replace` needed — the base manifest does not set
     `allowBackup`.)
   - Confirm **no** `INTERNET` permission is present (it is not today; re-check after
     the merge).

**Tests** (repository + resolver are testable now without the plugin)

5. `test/repositories/location_repository_test.dart` — save → read round-trip,
   missing key → `null`, corrupt JSON → `null`, `use live` default and toggle,
   `clear` removes the record. Uses `SharedPreferences.setMockInitialValues`.

6. `test/services/location_resolver_test.dart` — the fallback chain: live wins when
   `useLive` and success; falls back to saved when live off/failed; `null` when
   nothing available.

**Docs (after implementation, not code)**

7. `docs/implementation_progress.md` — tick the Phase 4 boxes and add a dated note.
8. `change_log/20260721_hhmmss_phase4-location.md` — the change log.

## Scope notes

- **No Riverpod providers here.** Wiring these into providers (active-location
  provider, settings) is Phase 5. This phase delivers the service, repository, pure
  resolver, manifest, and their tests.
- The polar (86,400 s) and before-sunrise (yesterday) fallbacks are already done in
  Phase 3's `SolarCalculator.resolveDay`; this phase only adds the
  **location-selection** fallback (live → saved → none).
- Hard rules kept: offline (GPS only, no `INTERNET`, no networking package); location
  stays on device (never sent, never logged); never crash on a missing anchor
  (resolver returns `null` → midnight day).
